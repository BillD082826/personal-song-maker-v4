## Meta callback preparation — November 2 (local, not deployed)

lib/meta-connection.mjs mounts before the general scheduler API at /api/admin/ad-scheduler/meta. It requires the same Admin login and both the planning flag and AD_SCHEDULER_META_CONNECTIONS_ENABLED=true. Defaults leave connection handling off. Required private configuration: META_APP_ID (Meta app ID), META_APP_SECRET (Meta app secret, not Instagram secret), META_LOGIN_CONFIG_ID (narrow reviewed configuration), AD_SCHEDULER_TOKEN_KEY (32 random bytes encoded as base64). Do not put secrets in chat, browser scripts, Git, logs or query strings sent to LyriBop. Keep the encryption key stable; rotation needs a separately reviewed re-encryption procedure.

POST /start requires canonical PUBLIC_BASE_URL Origin, JSON and scheduler header. It creates a ten-minute random request state and browser binding: only their SHA256 hashes go into PostgreSQL, while binding goes into a Secure/HttpOnly/SameSite=Lax cookie. GET /callback checks Admin, state/binding/config/expiry and atomically consumes state before handling the provider response. Replays fail. A declined or interrupted flow requires a fresh connection attempt. The server exchanges the one-use code with Meta and reads system-user identity and assigned Instagram accounts through fixed Meta endpoints. Errors are sanitized, provider redirects refused and requests time out.

Any returned token is AES256-GCM encrypted with an authorization/app/config binding before PostgreSQL storage. The browser receives only a pending-review ID and account names/IDs. Tokens/secret/code never appear in the callback response. Pending records have no publishing capability in this implementation; business ID/actual scope and intended asset verification still need review before activation. No automatic refresh/revocation/rotation or account-picker UI is implemented yet. No Facebook Page token/discovery is claimed; that integration remains separate work. Existing permissions alone are not a working connection.
