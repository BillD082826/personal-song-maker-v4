# Ad Scheduler — saved local planning stage

Open the Advertising Dashboard and select Ad Scheduler. Restart the local server after installing this change; an already running Python process cannot load its new API automatically. restart-dashboard.command checks that the listener belongs to this dashboard before restarting it. It is specific to Bill's Mac/project path. No Render deployment is needed for this local stage.

Plans are saved in .scheduler-data/plans.sqlite3, not browser storage. Clearing the browser does not erase plans. The database is excluded from Git and blocked from static HTTP access. Download Plan exports metadata/captions; Report CSV exports statuses. Neither export is a complete database/artwork backup. Existing disaster-backup inclusion of scheduler data is unverified. Keep this database when moving/reinstalling the dashboard; use SQLite's backup API for a consistent live copy.

Choose a saved Ready to Post single-image ad, platform, Eastern date/time and wording. Pinterest title/destination retained. Three standard daytime slots can fill the coming seven calendar dates for one platform; elapsed slots skipped, and same-ad repetition requires explicit batch confirmation. Select different ads/times individually for rotation. Saved default Draft/Archive ads are excluded and browser-local Draft/Archive overrides block saves. Planning does not change ad statuses.

Each plan keeps immutable caption/metadata and exact artwork bytes deduplicated by SHA256. View saved ad displays those bytes. Later source edits cannot silently change saved artwork. Cancel retains a report record; a replacement can use the released slot. Pause persists across restarts. Conflicting slots reject the entire batch atomically. Past/out-of-window instants and ambiguous/nonexistent DST times are rejected. UTC instants and Eastern wall times retained. Stale plans become Past due — review required; no backlog is sent.

This stage has no credentials, platform client, sender, timers or enable switch. Plans are explicitly not connected. The report never represents plans as published or fabricates confirmed timestamps/links. Existing manual Posting History is separate and untouched.

Stories/greetings/videos need separate format validation and are excluded from this first single-image stage. Mac-off scheduling is not implemented locally.
